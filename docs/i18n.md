# Languages & currencies

Noir Café is available in **English** (the default), **日本語**, **Français** and **Italiano**. Prices can be shown in **USD, EUR, JPY or GBP**. Every price is set and charged in US dollars; other currencies are shown as an approximate conversion.

## How a visitor gets their language

`src/proxy.ts` resolves the language on every page request, in this order:

1. **Saved choice.** This is the `noir-locale` cookie. It is set when someone switches language, or opens a `/ja`, `/fr` or `/it` URL.
2. **Browser language**, from the `Accept-Language` header.
3. **English.**

| Request | Result |
| --- | --- |
| English visitor opens `/menu` | Served as is. English URLs have no prefix and are internally rewritten to `/en/menu`. |
| Japanese visitor opens `/menu` | 307 redirect to `/ja/menu` |
| Anyone opens `/en/menu` | 308 redirect to the canonical `/menu` |
| Anyone opens `/de/menu` | 404 (not a supported language) |

All pages live under `src/app/[lang]` and are prerendered for all four languages: `generateStaticParams` with `dynamicParams = false`. Server code reads the language through `next/root-params` (`getLocale()` in `src/i18n/server.ts`).

The root layout sets `<html lang dir>`. Each page publishes a canonical URL and `hreflang` alternates for all four languages plus `x-default`. The sitemap lists all 44 URLs (11 routes × 4 languages) with their alternates.

Internal links use `@/i18n/link`, a drop-in replacement for `next/link` that adds the current language prefix. A Japanese visitor therefore never goes through a redirect.

## Where the words live

| Kind | File | How it's used |
| --- | --- | --- |
| Interface and metadata: navigation, dock, footer, newsletter, atmosphere controls, PWA prompts, page titles and descriptions, page intros | `src/i18n/dictionaries/{en,ja,fr,it}.ts`, keyed and typed | `getDictionary()` on the server, `useI18n().t` on the client |
| Page content: sections, data (menu, story, brewing, shop, locations), buttons, errors | `src/i18n/messages/tables/*.ts`, keyed by the English sentence | `tr("…")`: `getTranslator()` on the server, `useI18n().tr` on the client |

Page content uses the gettext approach: components are written in English and each string is wrapped in `tr()`. Data passes through `tr()` as it renders.

- In English, `tr` returns its input unchanged. English output is therefore exactly the source text, and English pages carry no translation payload.
- Each table entry keeps the English next to its Japanese, French and Italian, so translators review them side by side.
- `{name}` placeholders are filled by `tr(text, vars)`.
- `tr(text, null, "context")` separates two meanings of the same English word, for example "Brew" as a label versus "Brew" as a button.
- `rich()` places links inside a translated sentence, so each language keeps its own word order.

Drink names and internationally used coffee terms stay as they are, as the brief asks: Espresso, Latte, Cappuccino, Cortado, V60, Chemex, AeroPress, Bloom. Descriptions, tasting notes and everything around them are translated. The same applies to café names, street addresses and subway stations, which stay as New York writes them.

## Formatting

`useFormat()` on the client, or `src/i18n/format.ts` on the server:

- **Prices:** `Intl.NumberFormat` in the visitor's language.
  - English in USD is exactly the original `$6.50` / `$22`.
  - French renders `6,50 $US`.
  - With another display currency: `≈ 5,70 €`, `≈ ￥1,024` (yen always in whole units).
- **Dates:** `Intl.DateTimeFormat`, used for the reservation calendar, the pass, reviews and rate dates.
- **Times:** English keeps "10:30 AM"; other languages use their own clock. Pickup times use the New York time zone.
- **Units:** outside English, the locations page shows °C and kilometres.

## Currencies

`GET /api/currency` returns the European Central Bank's daily reference rates from USD, fetched from Frankfurter (no key needed) and cached for six hours. `?amount=6.5&to=JPY` converts one amount on the server.

- No rate is ever hardcoded.
- If the source is unreachable, the endpoint answers 503 and the site keeps showing US dollars.
- The currency choice lives in the phone and tablet menu sheet and persists per device.
- A note under the choice states that charges are in US dollars and gives the date of the rate.

## Typography

Japanese pages add **Noto Serif JP**, paired with Cormorant for display text, and **Noto Sans JP**, paired with Inter for body text. Latin letters keep the brand typefaces because those typefaces come first in the font stack.

- The Noto stylesheet is requested only on Japanese pages, and is inserted in a way that doesn't block rendering.
- It uses `display=optional`, so a font that isn't ready at first paint is not swapped in later. It is used from the next page view once cached, so Japanese pages cannot shift.
- The unicode-range slices download only for the characters actually on the page.
- If the fonts fail entirely, Japanese text falls back to Hiragino or Yu.
- Japanese line breaking uses `word-break: auto-phrase` and strict kinsoku (Japanese line-breaking rules).

French and Italian use the existing typefaces, whose Latin subset already includes their accents, `« »`, `€` and `’`.

## Right-to-left readiness

No right-to-left language is enabled yet, but the layout is ready for one:

- Each locale declares its direction, and the layout sets `dir` from it.
- Components use logical utilities (`ms-`/`me-`, `ps-`/`pe-`, `text-start`, `rounded-s`, `inset-s-`…). In a left-to-right document these resolve exactly like their physical versions, so nothing changes today.
- `npm run rtl:check` fails if a physical utility creeps back in. `node scripts/rtl-logical.mjs src` fixes it.
- The one exception is `left-1/2 -translate-x-1/2` centring, because `translate` has no logical form; the codemod leaves it alone.
- QA forces `dir="rtl"` on six key pages to confirm nothing overflows and spacing mirrors.

To add a right-to-left language:
1. Add it to `LOCALES` and `LOCALE_META` with `dir: "rtl"`.
2. Add a core dictionary.
3. Add a column to each table.

## The Concierge

The AI concierge replies in the visitor's language. The route appends a short "reply in …" line after the cached system prompt, so all four languages share one prompt cache. Product-mention cards also recognise the translated product names.

## Checks

```bash
npm run i18n:check   # every English source string has ja, fr and it (exit 1 if not)
npm run rtl:check    # no physical left/right utilities remain
```

Run `node scripts/i18n-check.mjs --unused` to list table entries nothing references literally. That includes strings reached through variables, such as API error codes, weather and per-roast lines.

## Review before launch

The Japanese, French and Italian translations were written for this build. They should be reviewed by native speakers before launch, particularly the marketing lines, which carry the brand's tone.
